# AIC-020 — постоянный персонаж и шлюз действий

Дата: 2026-11-10. Источник: [AI-001 §5](../../QUESTJOB/AI.md#5-контракты-действий-псевдо-go-адаптировать-к-реальным-пакетам). Это продолжение разрешённой реализации в feature/ai-civilization. Включение автономного director/canary не выполнено.

## Что реализовано

- Bootstrapper проверяет captain_id по активному Studio. Он вызывает общие world.CreatePilot/PGStore в одной транзакции с ai_agents. Никаких отдельных стартовых кредитов/XP/инвентаря. Повтор/гонка не создают второго player и не сбрасывают состояние. Некорректный ник/пол/направление отклоняются тем же сервисом, который теперь вызывает человеческий WS create_character.
- Произвольный Bind чужого существующего player запрещён. Сохранённый профиль связан1:1 с обычным players; изменения Studio не переписывают прогресс.
- Краткоживущая lease: криптослучайный токен в отдельном зарезервированном namespace aiciv2_, в БД только SHA-256. Новая lease отменяет старую; истёкший токен не становится гостем. Disable по умолчанию и повторная проверка lease на каждом AI intent, а не доверие флагу клиента.
- Gateway подключается только к loopback WS и не следует redirects. Он использует обычный обработчик, world проверки, квесты и прогрессию. Аккаунты/корпорации/чат/кошелёк напрямую не изменяет. Выбор цели не даёт скрытых координат.
- Подключены только move/target/autopilot/mine/mine_stop/attack и чтение pilot/ships/market. Buy/sell/repair/jump/ship_upgrade, корпорации и новый чат для этих акторов закрыты серверным capability-gate, включая прямой WS в обход контроллера.
- Журнал action receipts: один диспетчер на action_id, сравнение канонического запроса, replay готового ответа; pending/uncertain не исполняется вслепую. Timeout не возвращает фиктивный успех. Нельзя объявлять exactly-once side effect для будущих economic handlers на основании этого журнала.
- Технический бюджет canary ledger4096 ключей на капитана; после него новые команды отклоняются, старые receipts не удаляются ради replay. До массового live-режима нужен отдельный retention/recovery дизайн.
- AI метка в снимке мира серверная; AI не занимают human slots. Локальный лимит мира200 учитывает обычные AI-объекты и persistent actors. Глобальные квоты/совместное управление со старым Manager — AIC-030; текущий экспериментальный шлюз не является готовым population director.

## Включение и безопасность

COSMOC_AI_CIVILIZATION_GATEWAY=false по умолчанию; true требует COSMOC_FEATURE_AI. В main wiring есть защитный MarkedPlayers и AIActorGuard, но нет автоматического bootstrap/spawn 300 персонажей или вызова OpenGateway. Не включать production/canary до координации старой FSM и нового actor pool: видимый двойник капитана/квоты/уход при0 людях и горизонтальные миры требуют AIC-030. На тестовом локальном сервере Gateway подключён к настоящему WS и PG, а не fake successful adapter.

SQL0023 additive: leases/receipts. SQL0024 исправляет общий квестовый путь (см. ниже). Перед merge проверить номера свежей main. Rollback: flags off, не удалять players/имущество/таблицы. Оснащение и его ledger не заменены.

## Блокер общей экономики: AIC-025

В действующем WS buy списание предшествует AddCargo; repair/ship_upgrade также состоят из отдельных стадий. Нельзя объявлять атомарные, безопасные для retry команды AI поверх этого пути. Нужен общий authoritative command service с транзакцией/резервом, проверкой дока/груза/цены/ревизии, компенсацией и idempotent receipt для людей и AI. Это новая необходимая техническая зависимость, а не разрешение выдать AI отдельные привилегии. По решению владельца неподключённые capabilities остаются закрытыми; AIC-025 BLOCKED до этого общего этапа.

## Исправление общей добычи: AIC-024

До исправления mine event с Credits=0 отбрасывался в grantRewards, так как GrantCredits не выдаёт нулевые награды. Падающий TestMiningWithoutCreditsAdvancesQuestOnce показал progress0 вместо2. Теперь EventOnce сохраняет receipt и прогресс одной транзакцией без выдачи денег. Повтор/изменённый payload не дают вторую добычу в квесте; восстановление Join завершает уже накопленную цель, если сервер остановился до выплаты. Таблица quest_event_receipts общая для людей/AI; новые суммы XP/кредитов не выдуманы.

Это не делает груз и квест одной транзакцией: авария до доставки события из world в quest всё ещё требует durable domain outbox. Ранее зарегистрированный риск потерь прогресса при аварии полностью не закрыт.

## Следующая интеграция

AIC-030: director выдаёт реальные цели/планы, резервирует капитана против старой FSM, получает только видимые данные, управляет 0 humans/grace, восстанавливает активные intents и измеряет нагрузку. AIC-025: сначала атомарная общая экономика. Полные диалоги/социальные графы/аукцион/производство не входят в готовность этого checkpoint.
