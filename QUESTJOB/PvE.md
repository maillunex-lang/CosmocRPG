## 2. Цели и мотивация
Игрок должен получать: автономию (выбор маршрута, тактики, уровня риска), мастерство (понятные механики и прогресс навыка), социальную значимость (различимый вклад ролей), любопытство (секреты и новые ситуации), справедливые вознаграждения и возможность завершить полезную активность за короткую мобильную сессию.
Недопустимы: ежедневная обязаловка ради обязательного прогресса, неограниченный фарм через повторы, бессмысленные HP-губки, механики, требующие конкретного класса без альтернатив, скрытые шансы наград, фальшивые AI-союзники и платное преимущество.
Гипотезы проверять метриками: completion rate, retries, abandon reasons, median queue time, solo/group retention, распределение вкладов, разнообразие реально выбранных шаблонов. Не использовать манипулятивные FOMO-механики.

## 3. Каталог активностей и контент
Каждый тип реализовать через общий контракт `ActivityDefinition`, а не отдельный игровой движок.
1. **Solo Operations** (1 участник, 5–10 мин): аварийный маяк; поиск пропавшего исследователя; разведка конвоя; эвакуация под огнём; обезвреживание мин; защита ремонтной платформы. Начальный каталог 6 шаблонов, 2–4 вариации каждого. Без искусственной необходимости в группе.
2. **Active Expeditions** (1–4, 10–25 мин): граф 3–7 событий с выбором пути, угрозой, сканированием, редкими объектами, эвакуацией и фиксируемым решением. НЕ путать с AFK-экспедициями до 12 часов. Начальный каталог 4 архетипа (аномалия, древний объект, корабль-призрак, научный комплекс).
3. **Cooperative Operations** (2–5, 10–20 мин): сопровождение с разделением целей; одновременная защита и ремонт; захват контрольных узлов; отключение помех; эвакуация гражданских. 5 базовых сценариев, соло-альтернатива только там, где она честно достижима.
4. **Tactical Raids** (3–5, 20–35 мин; 6–10 только после нагрузочных тестов): фазы, телеграфы атак, уязвимые подсистемы, механики поддержки, смена приоритетов; не заменять уже существующего мирового «Левиафана», а подключать его к общему учёту событий и наград. 2 первых новых рейдовых сценария, не клоны босса.
5. **Regional Crises** (открытый мир, участие 3–15 мин в рамках событий до нескольких часов): нападение NPC, авария транспортного узла, перебои снабжения, спасение, зачистка маршрута. Влияние ограничено и обратимо; не изменять произвольно экономику и PvP-юрисдикцию.
6. **Corporate Operations** (многоэтапные): снабжение, инженерная подготовка, разведка, оборона, финальная операция; использовать будущий корпоративный домен и QUEST-09, не создавать вторую корпоративную систему.

Для каждого шаблона обязательно: ID/версия; narrative hook; регион/фракции/системы; required_capabilities; min/max party; соло-доступность; цели, failure/success; ориентир длительности; risk band; доступные роли; карта/спавны; вариации; стадии и переходы; телеграфы; подсказки; награды и ограничения; accessibility; тестовые сценарии. Числа — стартовые балансировочные предложения, не окончательные утверждённые коэффициенты.

## 4. Генератор разнообразия
`ScenarioComposer` строит сценарий из совместимых слоёв: основная цель × окружение × тип противников × тактический модификатор × необязательное осложнение × развилка × награда. Слои валидируются constraint graph: не создавать неразрешимые сочетания, невозможные цели, взаимоисключающие фазы, недостижимые объекты или требования отсутствующих модулей.
Seed = H(activity_definition_version, instance_id, region_id, generation_revision, server_secret_salt); сервер сохраняет seed, итоговый граф и content version. Повтор после рестарта воспроизводит сценарий, но не выдаёт награды повторно. Клиент не выбирает seed. Весовые таблицы предотвращают чрезмерные повторы; pity на конкретную редкость не вводить без сверки с loot.md. Сюжетные миссии не рандомизировать без согласования с FinalQuest.md.
Первый вертикальный срез: 3 задачи × 3 окружения × 3 осложнения, но только проверенные допустимые комбинации. Автотест перебора 10 000 seed и проверка достижимости каждого графа.

## 5. Архитектура Go
Предлагаемые логические интерфейсы (имена адаптировать к существующим пакетам):
```go
type ActivityDirector interface {
  Discover(ctx context.Context, actor ActorRef, filter ActivityFilter) ([]ActivityOffer, error)
  Create(ctx context.Context, actor ActorRef, definitionID string, requestID string) (ActivityID, error)
  Join(ctx context.Context, actor ActorRef, activityID ActivityID, requestID string) error
  Act(ctx context.Context, actor ActorRef, activityID ActivityID, action ActivityAction) (ActivityEvent, error)
  Leave(ctx context.Context, actor ActorRef, activityID ActivityID, requestID string) error
}
type ActivityDefinition struct {
  ID string; Version int; Mode string; MinParty int; MaxParty int
  RequiredCapabilities []string; Objectives []ObjectiveSpec
  Stages []StageSpec; RewardPolicyID string; RiskPolicyID string
}
type ActivityEvent struct {
  ID string; ActivityID string; ActorID string; Kind string
  OccurredAt time.Time; Sequence int64
}
```
Сервисы: ActivityCatalog, ActivityDirector, ScenarioComposer, ObjectiveEvaluator, EncounterAdapter, ParticipationLedger, RewardSettlement, PartyMatchmaker, RegionalEventScheduler, PvEAnalytics, ContentValidator. Не дублировать домены Combat/Quest/Loot/Worldgen.
Состояния: OFFERED → FORMING → READY_CHECK → ACTIVE → {COMPLETED | FAILED | ABANDONED | EXPIRED} → SETTLED → ARCHIVED. Отдельные состояния PAUSED/RECOVERING только при определённой политике. Переходы строго серверные, с revision/optimistic concurrency, idempotency key, audit trail и проверкой прав. Никаких прямых начислений из WS-handler.
Серверные события objective_progress, objective_completed, phase_changed, participant_joined/left, activity_completed, reward_settled, event_expired. Процессор не должен держать глобальный lock во время БД и внешних операций. Тики/таймеры серверные, ограниченные CPU-budget; дальние региональные события агрегировать, не держать 3D-симуляцию всех объектов.

## 7. Поиск группы и командная игра
`PartyMatchmaker` сначала проверяет уже существующие группы/социальные API. Если их нет — узкий адаптер PvE-ticket без второй глобальной системы гильдий/друзей. Режимы: одиночный, готовая группа, автоматический подбор, поиск с друзьями, разрешить AI, только люди.
Ticket: actor_id, activity_id, tier, region, latency band, ship build snapshot revision, role_preferences, expected_duration, language preference (при наличии), allow_ai, created_at. Сопоставление по допуску контента, региону, пингу, роли и предпочтениям; не обещать точное время ожидания без статистики. По мере ожидания постепенно ослаблять необязательные предпочтения, но никогда не нарушать минимальные требования безопасности и мощности. Показывать статус и кнопку отмены.
Ready check 30 секунд (настраиваемо); лидер не может принудительно начать без согласия участников, кроме разрешённого solo. Роли: защитник, атакующий, инженер/поддержка, разведчик/контроль, универсальный; класс корабля не обязан жёстко соответствовать роли. Переходы групповых фаз не требуют одного уникального класса без доступной альтернативы.
При дисконнекте: grace 120 секунд по умолчанию, место сохраняется; повторный вход восстанавливает снапшот; после grace участник помечается offline и может быть заменён только по правилам активности. Вступление в середине — только в допустимой фазе и без ретроактивной награды. AFK: измерять участие, предупреждать, не поощрять пассивное ожидание; не наказывать поддержку за низкий DPS.
AI-союзники: только полноценные AI-PLAYERS через ActionGateway и те же требования, стоимость, потери и награды. Пока capability отсутствует — скрыть опцию, не подменять AI статическим дроном с фальшивым аккаунтом. Определение AI видно в профиле, отдельная опция «только люди». Запрещены привилегированные телепортации, бесплатные расходники и фиктивный прогресс.

## 8. Масштабирование сложности и Gear Score
Боевой GS — ориентир допуска/рекомендации, не гарантия победы. Учитывать тип урона, устойчивости, мобильность, тактическую роль, уровень, специализацию, расходники и реальный loadout. Промышленный рейтинг и мощь флота не подменяют боевой GS.
Начальная рекомендательная функция для тестирования:
`TargetPower = BasePower(tier, region) * (1 + 0.30 * (effective_party_size - 1)) * EncounterModifier`.
Это НЕ финальная формула HP/урона: разделять здоровье, количество целей, механики и интенсивность атак, чтобы группа не получала лишь HP-губку. Коэффициенты подбирать симуляциями; ограничения на power spread, входы low-level с наставниками и abuse prevention.
Три полосы риска: стандартная, опасная, экстремальная. Соло-версия не обязана давать тот же объём лута за единицу времени, но не должна закрывать базовую прогрессию. Сложность показывать заранее, включая риск потерь.

## 9. Экономика, награды, потери
Все награды через существующий Loot/Reward/XP ledger и подтверждённые доменные события. Формула планирования бюджета: `ExpectedNetValue = BaseBudget(tier, duration) * RiskFactor * ObjectiveQuality`, с серверными ограничениями по экономике и без оплаты за бессмысленные циклы; это ориентир для балансировки, не новая независимая касса.
Выдача: гарантированная базовая награда при выполнении порога + вероятностные предметы по loot.md + бонус за дополнительные цели. Участие: damage, tanking, healing, repair, scouting, interrupts, objective work, escort protection; нормализовать и ограничивать, не допускать self-farm и накрутки аффилированными аккаунтами. Списания ресурсов/ремонт/страховка — реальные; убытки и право на обломки строго по loot.md. Не создавать предметы, рецепты, rarity или drop rates в обход каталога.
Повторное прохождение возможно, но прогрессия наград и лимиты редких предметов конфигурируемы и прозрачны. Ежедневные/недельные активности — дополнительный маршрут, не обязательная монополия на ресурсы. Экономический мониторинг: credits minted/burned, rare items minted, cost of repairs, reward per active minute, region supply, bot abuse.

## 10. Открытый мир, PvP и инстансы
В открытом космосе PvE не предоставляет автоматический PvP-иммунитет, отдельную безопасную юрисдикцию или бесплатную эвакуацию. Соблюдать AR-1, CanAttack, docking, стартовый регион, права на salvage и страхование. Смерть/отступление/срыв задания учитываются честно.
**Неутверждённая концептуальная развилка PvE-002:** режим безопасности закрытых инстансов. До выбора владельца НЕ реализовывать новые PvP-исключения; первый вертикальный срез строить в существующем мире по текущим правилам. Любые private-instance правила согласовать отдельно. Инстансы не должны создавать копию всей галактики; использовать ограниченную серверную encounter-scene/область только если утверждено.

## 11. Godot 4 / Android UI
Раздел «Активности» в существующем навигационном центре: карточки (тип, регион, 1–5 участников, длительность, GS-рекомендация, риск, награды, PvP-статус), фильтры, карта, журнал. Экран поиска группы: очередь, роли, разрешить AI, приглашения, ready-check, переподключение, выход. В HUD: 1–3 активные цели, индикатор фаз, таймер только где нужен, маркеры целей, предупреждения атак и вклад поддержки; не загромождать ландшафтный экран.
Godot получает snapshot + последовательные server events по WS; event seq, ack/resync, устаревшие пакеты игнорируются, UI не определяет награды. Анимации/3D/иконки — переиспользуемые; низкий пресет графики и мобильные устройства обязательны; тяжёлый контент доставлять существующим механизмом пакетов после готовности, не раздувать APK. При потере сети показывать RECOVERING, не утверждать победу до server settlement.
Доступность: различать опасности не только цветом, регулируемая интенсивность эффектов, читаемые иконки, опциональные подсказки фаз, без обязательной голосовой связи.

## 12. Сетевые контракты (предложение, адаптировать к текущему WS)
Команды: `pve.list`, `pve.inspect`, `pve.create`, `pve.queue.join`, `pve.queue.cancel`, `pve.ready`, `pve.leave`, `pve.interact`, `pve.resync`, `pve.claim`. Каждый запрос: request_id, actor auth from session (не из клиента), expected_revision where relevant. Ответы: accepted/rejected с reason codes, instance_id, revision, state, authoritative timestamps. Server push: `pve.snapshot`, `pve.phase`, `pve.objective`, `pve.party`, `pve.reward`, `pve.error`. Versioned schema, backward compatibility, feature flags; не ломать legacy protocol1.
Типичные reason codes: FEATURE_DISABLED, CAPABILITY_MISSING, NOT_ELIGIBLE, QUEUE_CONFLICT, PARTY_FULL, ROLE_MISMATCH, STALE_REVISION, ALREADY_SETTLED, NOT_IN_RANGE, OBJECTIVE_LOCKED, INSTANCE_EXPIRED, RECONNECT_REQUIRED. Rate limits, payload caps, permissions, audit.

## 13. Админка и контент
Расширить существующую Universal Space Studio/Quest Studio через адаптер PvE: каталог определений, шаблоны, матрица совместимости, условия, волны, награды (только ссылки на Loot), карта размещения, доступность по регионам, версии, черновик → проверка → предпросмотр → публикация → откат. Публикация новой версии не переписывает активные инстансы; они закреплены за прежней версией до завершения. RBAC и аудит действий администратора.

## 14. Тесты и эксплуатация
Unit: переходы FSM, проверки прав, генерация seed, расчёт вкладов, ограничения наград, роли. Integration: Quest/Combat/Loot/XP/AI capability gates, WS reconnect, DB rollback. Property/fuzz: 10 000 seed, отсутствующие цели, пересечение фаз, невозможные группы. Security: повторные запросы, race join/leave, двойной claim, поддельные координаты, подмена GS, боты, повторное подключение и stale revision. Chaos: restart на каждом этапе, DB timeout, двойной event, потеря WS, лидер выходит, AI исчезает, региональное событие завершается. Load: прототип 30–100 человек, затем 100+ по отдельным профилям, лимиты на число активных encounter и тики; измерять p95 latency, CPU, RAM, DB queries, WS bytes, Android FPS.
Критерий DONE для каждого этапа: сценарий реально проходим, награда не дублируется, PvP/лут/XP совместимы, миграции обратимы или есть план восстановления, CI зелёный, мобильный UI читаем, rollback/feature flag проверены, владелец разрешил следующий этап.
