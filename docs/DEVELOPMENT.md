# Правила разработки

Каждый этап содержит: цель, список файлов и модулей, план изменений, реализацию, автотесты, ручную проверку, результат сборки, обновление документации, коммит и отчёт.

- Не переходить к следующему этапу при критических ошибках предыдущего.
- Не заявлять о тесте, который не запускался. Не создавать фиктивные скриншоты, результаты тестов и отчёты.
- Нет доступа к инструменту: честно сообщить, что операция не выполнена.
- Технологический стек не менять без обоснования и разрешения владельца.
- Утверждённые решения ([DECISIONS.md](DECISIONS.md)) не менять без согласования.
- Не использовать инфраструктуру, домены, базы и ресурсы других проектов.
- Секреты не коммитить.
