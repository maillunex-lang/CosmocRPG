# Архитектура

## Общая схема

```
Godot-клиент (Android)  --HTTPS/WS-->  Игровой сервер (Go)  -->  PostgreSQL
                                              ^
Админка (React+TS)  ------HTTPS/JSON----------+
```

Сервер авторитетный. Клиент отправляет команды (намерения), сервер валидирует, считает и рассылает состояние.

## Единственный источник истины — сервер

Координаты и движение, характеристики кораблей, здоровье, урон и способности, предметы и ресурсы, валюта и сделки, исследования и производство, результаты idle-заданий, репутация и корпоративное имущество.

## Клиент (`client/`)

Три слоя: сеть (WebSocket, сериализация команд), отображение (сцены, 2.5D-камера, 3D-корабли в SubViewport/3D-слое), ввод (касания, автопилот, способности). Слои общаются сигналами; отображение не ходит в сеть напрямую.

## Сервер (`server/`)

Go, модульная структура:

- `cmd/server` — точка входа, конфиг из переменных окружения, корректное завершение;
- `internal/config`, `internal/log` (структурированные логи), `internal/db` (PostgreSQL, миграции);
- `internal/http` — health, REST для админки и аккаунтов;
- `internal/ws` — сессии, проверка команд, защита от повторного использования токена;
- игровые модули (позже): мир, движение, бой, экономика, idle, фракции, AI.

Серверные события и фоновые задачи: планировщик заданий с идемпотентным завершением (повторная обработка не создаёт дубликатов).

## База данных

PostgreSQL, версионируемые миграции, ограничения целостности. Валютные и предметные операции только в транзакциях. Журнал создания и уничтожения валюты. Порт БД не публикуется наружу.

## Админка (`admin/`)

React + TypeScript. Серверная авторизация, журнал административных действий. Контент: Черновик → Валидация → Предпросмотр → Ручная публикация, с откатом версии (поздние этапы).

## AI-капитаны

Активная система: команды через обычный серверный API. Удалённые системы: событийная симуляция. Дальние организации: агрегированная симуляция. Постоянной языковой модели на капитана нет.

## Idle

Задания хранятся на сервере, результат считается по серверному времени. Удалённые корабли не симулируются в 3D непрерывно.

## Развёртывание

Docker Compose: `server`, `postgres`, `admin`. Подробности в [DEPLOYMENT.md](DEPLOYMENT.md).
