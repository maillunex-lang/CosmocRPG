# codex-security-review: Уралия

## Порядок работы
1. Сначала определи реальные границы доверия по `docs/ARCHITECTURE.md`, `server/`, `schemas/`, `docs/CI.md`. Godot-клиент не является источником истины для боя и наград.
2. Проверяй повторные запросы, идемпотентность выдачи наград, дублирование валют, подмену результата боя, race conditions и повторную выдачу first-clear.
3. Проверяй авторизацию, резервный код, сессии, роли владельца, права редакторов и аудит изменений без вывода секретов.
4. Проверяй загрузки ZIP/ресурсов, манифесты, проверку хэшей, лимиты размеров и запрет исполнения недоверенного кода.
5. Проверяй GitHub Actions на избыточные permissions, небезопасные выражения shell и попадание секретов в артефакты.
6. Отчёт: файл/строка, риск, воспроизведение на тестовых данных, безопасное исправление. Никаких тестов на живом VPS или production без отдельного разрешения.

## Общие ограничения
Работать только в `maillunex-lang/ufa5` по согласованной задаче. Сверять утверждённые решения с кодом, не переносить 3D MMORPG-механики из AnimeAutoMMORPG. Не трогать Claude MCP, Codex MCP, VPS, другие репозитории, занятые порты, production, секреты и платежи. Никаких внешних зависимостей или исполняемых хуков без аудита и разрешения. Отчёт о файлах, реальных проверках, рисках и следующем шаге.

## Происхождение
Оригинальная адаптация рабочих принципов из собственного репозитория `maillunex-lang/AnimeAutoMMORPG/.agents/skills/codex-security-review/SKILL.md`; инструкции переписаны под существующую архитектуру Уралии. Сторонний код не добавлен.
