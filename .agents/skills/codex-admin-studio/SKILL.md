# codex-admin-studio: Уралия

## Порядок работы
1. Изучи `docs/tz/TZ_ADDENDUM_02_UI.md`, `docs/design/WORLD_CONTENT_SCHEMA.md`, `docs/DECISIONS.md`, существующие `schemas/`, `data/` и фактический код админки.
2. Разрабатывай по одному редактору: герои, враги, умения, карта, этапы, награды, интерфейсы, события; не строй новый монолит.
3. Процесс: черновик → проверка схем и ссылок → предпросмотр → ручная публикация. Не публикуй изменения автоматически.
4. Стабильные ID, версии данных, журнал правок, проверка зависимостей перед удалением; используемые объекты удалять только по утверждённым правилам компенсации.
5. ZIP-моды считать недоверенными: защита от path traversal, zip bombs, исполняемого кода, неразрешённых типов и конфликтов; не выполнять загруженные скрипты.
6. Платежи и production-публикацию не включать. Для теста использовать изолированные фикстуры и имеющиеся валидаторы, включая `tools/validate_world.py`.

## Общие ограничения
Работать только в `maillunex-lang/ufa5` по согласованной задаче. Сверять утверждённые решения с кодом, не переносить 3D MMORPG-механики из AnimeAutoMMORPG. Не трогать Claude MCP, Codex MCP, VPS, другие репозитории, занятые порты, production, секреты и платежи. Никаких внешних зависимостей или исполняемых хуков без аудита и разрешения. Отчёт о файлах, реальных проверках, рисках и следующем шаге.

## Происхождение
Оригинальная адаптация рабочих принципов из собственного репозитория `maillunex-lang/AnimeAutoMMORPG/.agents/skills/codex-admin-studio/SKILL.md`; инструкции переписаны под существующую архитектуру Уралии. Сторонний код не добавлен.
