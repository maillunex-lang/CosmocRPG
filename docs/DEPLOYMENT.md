## Окружение

- VPS: `78.17.214.25`, Ubuntu 24.04, 4 CPU, 7.8 ГБ RAM, 59 ГБ диск.
- Установлено: Docker 29.1.3, Docker Compose 2.40.3, Go 1.22.2, psql 16, Node 26, Godot 4.7.2, Blender 4.0.2, Android SDK (`~/Android/Sdk`: build-tools 35.0.1, platform 35, NDK 28.1.13356709), JDK 17.
- Домена нет: доступ по IP, без TLS у игрового порта; админка по HTTPS с самоподписанным сертификатом.

## Запуск и управление

Секреты вне репозитория: `~/keys/cosmoc/stack.env` (права 600; образец: `infrastructure/.env.example`).

```bash
DC="sudo docker compose -f infrastructure/docker-compose.yml --env-file $HOME/keys/cosmoc/stack.env"
$DC up -d --build        # собрать и запустить
$DC ps                   # состояние
$DC logs -f server       # журнал сервера
$DC down                 # остановить (данные в томах сохраняются)
```

Создать администратора (пароль через stdin, не аргументом):

```bash
printf '%s\n' "ПАРОЛЬ_12+_СИМВОЛОВ" | $DC exec -T -e COSMOC_ADMIN_USERNAME=имя server /server admin-create
```

Текущий администратор `owner`; пароль в `~/keys/cosmoc/admin_login.txt` (права 600).

## Доступ к админке

Адрес: **https://78.17.214.25/admin/** (порт 443, путь `/admin/`; корень `/` перенаправляет в `/admin/`).

- Сертификат самоподписанный (внутренний CA Caddy), домена нет: браузер покажет предупреждение, нужно выбрать «продолжить». Трафик при этом шифруется; от подмены сертификата без проверки отпечатка это не защищает. С появлением домена перейти на обычный сертификат.
- Вход по логину и паролю; после 5 неудачных попыток вход блокируется на 15 минут (по IP и по имени).
- Закрыть админку от интернета: `ADMIN_BIND=127.0.0.1` в `~/keys/cosmoc/stack.env`, перезапуск стека; тогда вход через SSH-туннель: `ssh -L 443:127.0.0.1:443 gamedev@78.17.214.25` (локальный порт 443 требует прав, можно `-L 8443:127.0.0.1:443` и адрес `https://localhost:8443/admin/`).
- Маршрутизация Caddy: `/admin/api/*` -> админ-API сервера (:8081 во внутренней сети, префикс `/admin` отбрасывается), `/admin/*` -> статика админки.

## Файрвол

Docker публикует порты в обход `ufw`, поэтому реальная защита: привязка портов к `127.0.0.1` (админка) и отсутствие публикации (PostgreSQL, админ-API :8081). `ufw` разрешает SSH (22), игровой порт (8080) и HTTPS админки (443).

## CI/CD

`.github/workflows/ci.yml`: проверки сервера (gofmt, vet, тесты с race и PostgreSQL), админки (типы, тесты, сборка), клиента (импорт проекта в Godot, тесты сети и экрана), сборка Docker-образов; артефакты: бинарник сервера и сборка админки. Автодеплой в production не включён. Сборка APK в CI и release-подпись через GitHub Secrets добавляются на этапе UI-12.

## Резервное копирование и восстановление

- `infrastructure/backup.sh`: `pg_dump` из контейнера, gzip, проверка целостности (архив, размер, маркер конца дампа), SHA-256, ротация (по умолчанию 14 дней). Каталог `~/backups/cosmoc` (права 700, файлы 600).
- Расписание: ежедневно 03:30, cron пользователя `gamedev`; журнал `~/backups/cosmoc/backup.log`.
- `infrastructure/restore-test.sh [файл]`: проверяет SHA-256, разворачивает копию во временную базу `cosmoc_restore_test` внутри контейнера postgres, сверяет число строк по таблицам с рабочей базой, удаляет временную базу. Рабочая база не затрагивается. Испорченная или отсутствующая копия даёт код выхода 1.
- **Ограничение:** копии лежат на том же VPS. При потере сервера они пропадут. Нужна регулярная копия вне сервера (решение и место хранения за владельцем).
- Восстановление рабочей базы из копии (аварийно): остановить `server`, затем `zcat копия.sql.gz | $DC exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'` (дамп содержит `DROP ... IF EXISTS`), запустить `server`.

## Публикация релиза и проверка обновлений (2026-11-08)

1. Поднять номер версии в `client/project.godot` (`config/version` и `cosmoc/version_code`) **и** в `client/export_presets.cfg` (`version/name`, `version/code`); тест `updater_test` проверяет, что они совпадают. Код версии только растёт.
2. Собрать подписанный APK: `. ~/keys/cosmoc/release.env && godot --headless --path client --export-release "Android" <файл.apk>`; проверить `apksigner verify` (отпечаток сертификата как в `docs/SECURITY.md`).
3. Опубликовать: `tools/publish_release.sh <файл.apk> "<что нового>"` (необязательно `MIN_CODE=<n>` — минимальная поддерживаемая версия). Скрипт копирует APK в `~/apk-share` (раздаётся Caddy по `https://rikagro.ru/download/`), пишет `latest.json` (версия, ссылка, размер, SHA-256, описание) и подпись `latest.json.sig` (RSA-SHA256, base64), проверяет подпись публичным ключом до публикации.
4. Клиент при запуске и по кнопке «Проверить обновления» скачивает манифест и подпись по HTTPS, проверяет подпись вшитым публичным ключом (`client/assets/update_public.pem`), сравнивает версии, отклоняет откат и небезопасные ссылки, показывает окно; «Обновить» открывает ссылку на APK, установку подтверждает пользователь в Android.
5. Приватный ключ подписи манифеста: `~/keys/cosmoc/manifest_private.pem` (вне репозитория, права 600). **Резервную копию ключа нужно хранить вне VPS** (как release-keystore); при потере придётся выпустить APK с новым публичным ключом вручную.

## Докачка контента без переустановки APK (2026-11-08, версия 0.3.3)

Игра при запуске (и по кнопке «Проверить обновления») скачивает подписанный `https://rikagro.ru/download/content/content.json` (+ `.sig`), сверяет подпись тем же ключом, что и обновления APK, и докачивает пакеты `.pck` (SHA-256, размер, ≤64 МБ пакет, ≤200 МБ всего). Пакеты применяются при следующем запуске (автозагрузка `ContentBoot` до загрузки сцен) и заменяют одноимённые файлы `res://`.

Публикация: `tools/publish_content.py <id пакета> <версия> <файлы под client/assets/…>` — собирает пакет, кладёт в `~/apk-share/content/`, обновляет и подписывает `content.json`. Версия пакета только растёт. Допустимы ресурсы (glb, png, jpg, webp, svg, ogg, mp3, wav) и данные (json, txt, csv); скрипты и сцены инструмент не принимает. Для пакета, которому нужна более новая версия приложения, задаётся `MIN_APP`. Переключатель «Автообновление контента» — в настройках игры.

Ограничение: изменения, которые требуют нового кода (скрипты, сцены, новые экраны), по-прежнему идут новым APK.

## Сборка Android через gradle и установка обновления из игры (2026-11-08, версия 0.3.4)

С версии 0.3.4 APK собирается шаблоном gradle (`client/android/build`, `gradle_build/use_gradle_build=true`, `compress_native_libraries=true` — иначе APK вдвое больше). Свой код: `ApkInstallerPlugin.java` (плагин Godot «ApkInstaller»), `UpdateFileProvider.java`, `res/xml/update_paths.xml`, разрешение `REQUEST_INSTALL_PACKAGES` в `src/main/AndroidManifest.xml`. Каталог `libs/` шаблона в git не хранится: на новой машине `unzip` из `~/.local/share/godot/export_templates/4.7.2.stable/android_source.zip` только `libs/*` и `gradle/*` в `client/android/build/` (остальные файлы не затирать, они изменены). Нужны `ANDROID_HOME=~/Android/Sdk`, Java и доступ к services.gradle.org при первой сборке. Команда сборки прежняя: `. ~/keys/cosmoc/release.env && ANDROID_HOME=~/Android/Sdk godot --headless --path client --export-release "Android" <apk>`.

Установка из игры: «Обновить» скачивает APK в `user://updates` (проверка размера и SHA-256 из подписанного манифеста), затем запускает системный установщик; при первом разе Android просит разрешить установку из этого источника. Если плагина нет (не Android, старая сборка), ссылка открывается в браузере, как раньше. Версии ≤0.3.3 так обновиться не могут: 0.3.4 ставится один раз вручную.

## ИИ-игроки (2026-11-09, ИИ-1)

Флаг `COSMOC_FEATURE_AI` (в compose по умолчанию `true`, `FEATURE_AI=false` выключает). Агент (`server/internal/aiagent`) раз в 2 с сверяет число ИИ с целью: без живых игроков — 0 (после задержки 30 с), при игроках от 20 до 50 (чем больше игроков, тем ближе к 50; потолок 200), набор не быстрее 12 в минуту, снятие не быстрее 30. Профили берутся из действующей версии AI Studio (капитан не появляется дважды, недавно ушедший не возвращается сразу). Настройки лежат в таблице `ai_settings` (миграция 0016, по умолчанию — значения R-42); редактирование из админки — этап ИИ-3, до него правятся SQL-запросом. Поведение по профессии: шахтёры (шахтёр, сборщик утиля) летают между месторождениями и станцией, торговцы курсируют между станциями, разведчики облетают точки, наёмники патрулируют, остальные держатся у станций. Экономику ИИ не затрагивают.

## Лендинг (2026-11-08)

Статический сайт в каталоге `site/` (HTML, CSS, JS, изображения; без внешних скриптов и шрифтов, без встроенных стилей из-за CSP). Копируется в образ Caddy (`COPY site /site` в `infrastructure/caddy/Dockerfile`) и отдаётся на корне домена `https://rikagro.ru/` и `www`; админка остаётся на `/admin/`, игра `wss://rikagro.ru/ws`, раздача APK и манифеста `/download/`. Страница получает версию, размер и ссылку скачивания из `/download/latest.json` (ссылка принимается только `https`, на этот же сайт, путь `/download/…apk`). В `/download/` APK отдаётся с типом `application/vnd.android.package-archive` и `Content-Disposition: attachment`, JSON с `application/json`. Страница помечена `noindex` (альфа для своих). Выкатка: `docker compose … up -d --build --no-deps caddy`. Изменение Caddyfile для лендинга разрешено владельцем (R-39).
