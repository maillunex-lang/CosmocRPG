# Выпуск в игру и APK (R-63)

Изучены записи Claude в docs/HANDOFF.md (0.3.3 content, 0.3.4 APK installer, последующие релизы), docs/DEPLOYMENT.md, tools/publish_release.sh, client/ui/{updater,apk_installer,app_version}.gd. Существующий механизм сохраняется.

1. Разрабатывать сквозными шагами на Стриже, сохранять старый протокол и старые характеристики. Проверить сервер, UI, повторный вход, затем собрать release-кандидат.
2. Для APK повысить версии согласованно в client/project.godot (config/version и cosmoc/version_code) и client/export_presets.cfg (version/name, version/code). Сверить updater_test. Не занимать номер релиза до готового сборочного кандидата и сверки main/последнего опубликованного манифеста.
3. Android release требует существующий постоянный ключ подписи приложения и рабочий Gradle-шаблон/SDK/AAR (см. записи Claude/Kimi). Ключи не создавать взамен прежних: Android иначе откажет в обновлении установленной игры. Собирать в отдельный каталог, не в каталог раздачи.
4. Проверить подпись APK тем же сертификатом, manifest version code/name и предел 95 MiB. tools/publish_release.sh копирует APK и публикует latest.json + RSA-SHA256 latest.json.sig с прежним ключом манифеста. Он не является инструментом сборки, и имя входного файла не доказывает версию/подпись содержимого. Не запускать его для чернового/непроверенного APK.
5. Updater получает подписанный манифест по HTTPS rikagro.ru, проверяет подпись, хост и защиту от отката. ApkInstaller скачивает файл, сверяет размер/SHA-256 и запускает Android-установку с подтверждением. Если плагин недоступен, используется безопасная ссылка в браузере. Данные сохраняются при совпадении app ID и ключа подписи.
6. После разрешённой публикации проверить реальный signed manifest: со старого кода available, с нового up_to_date. Установка поверх существующей версии на Android — отдельная фактическая приёмка, не заменяется headless тестами. На скриншоте пользователя установлена 0.3.10 (13); в исходниках main — 0.3.11 (14). Это не доказательство текущей версии на сервере: перед выпуском сверить публикацию отдельно.

## Состояние окружения
Текущий cloud executor не VPS. Найдены Java и Godot4.6.3; SDK tools adb/apksigner/sdkmanager не найдены в PATH, /opt содержит только Godot4.6.3 (CI использует4.7.2). Release credentials не настроены через окружение. Ключи/секреты не запрашивать в чате и не коммитить. Сборку/публикацию APK пока нельзя объявлять выполненной. Код updater/подписей не менять для обхода этих ограничений.

## Публикация работы для других ИИ
В main должны быть актуальные docs/ROADMAP.md, docs/HANDOFF.md и подробные ships-rpg/{ROADMAP,ERROR_LOG,REGRESSION_TESTS,HANDOFF}.md. До push сверить удалённую main, интегрировать чужие изменения без force, запустить применимые тесты. В отчётах различать: код/данные в main; CI; тестовая игра; production сервер; опубликованный/установленный APK. GitHub CI не делает production-деплой. Историческое постоянное разрешение не отменяет текущий запрет production без отдельного согласования.
