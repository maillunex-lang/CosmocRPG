# Этап 01 — общий онлайн-космос: план и протокол (на согласование)

Статус: **утверждено владельцем (токен устройства, радиус 400 ед. и скорость 14 ед/с, бот) и реализовано 2026-11-08.** Отличие от проекта: в `join` добавлено необязательное поле `name` (нужно боту; смена имени игроком по-прежнему позже). Формат сообщений: `docs/API.md`
(`{ "type", "id", "payload" }`). Все числа и права определяет сервер; клиент только показывает и шлёт намерения.

## Цель и границы

Одна звёздная система. Корабли игроков (и бот для проверки) видят друг друга. Движение от джойстика и автопилот
к выбранной цели. Сохранение координат, отключение и переподключение. **Не входит:** бой, способности, энергия,
щиты, экономика, чат, задания, аккаунты с паролями (это следующие этапы).

## Личность игрока

- Аккаунтов пока нет. Клиент при первом запуске создаёт случайный токен устройства (128 бит), хранит его локально.
  Сервер хранит только SHA-256 токена. Токен = игрок; по нему возвращаются координаты.
- Имя по умолчанию «Пилот-NNNN» (из токена). Смена имени позже, вместе с аккаунтами.
- Ограничение: игровой трафик идёт по `ws://` (решение владельца), токен виден в сети. Для теста допустимо; домен
  и TLS в бэклоге. Токен не даёт ничего, кроме позиции тестового корабля.

## Сообщения

Клиент → сервер:

| type | payload | Примечание |
|---|---|---|
| `join` | `{token, protocol: 1}` | Первое сообщение. До него остальные отклоняются. |
| `move` | `{x, y}` | Желаемое направление в мировых осях, длина 0..1 (клиент уже повернул вектор джойстика по камере). Только при изменении, не чаще 10/с. |
| `target` | `{id}` | Выбор цели (пустая строка снимает). Нужна для автопилота. |
| `autopilot` | `{on}` | Лететь к выбранной цели, остановиться на безопасном расстоянии. Ручной ввод `move` отключает автопилот. |
| `ping` | — | Как сейчас. |

Сервер → клиент:

| type | payload | Примечание |
|---|---|---|
| `hello` | как сейчас | До `join`. |
| `welcome` | `{player_id, name, system: {id, name, background}}` | Ответ на `join`. |
| `state` | `{time, ship: {name, pos, dir, speed}, objects: [{id, kind, stance, name, pos, dir}], target_id, autopilot}` | 10 Гц. Формат совпадает с тем, что уже ест HUD (`docs/ui/ACTION_REGISTRY.md`). `pos`, `dir` — массивы `[x, y]`. Объекты — остальные игроки и бот, `stance = "neutral"`. |
| `error` | как сейчас | Коды: `not_joined`, `bad_token`, `bad_protocol`, `rate_limited`, `replaced` (тот же токен вошёл с другого устройства). |

Протокол Этапа 00 (`hello`, `ping`/`pong`, `error`) не меняется, добавляются новые типы. Версия протокола в `join`:
несовместимый клиент получает `bad_protocol`.

## Сервер

- Пакет `world`: система, игроки, цикл симуляции 20 Гц, рассылка `state` 10 Гц. Сервер ограничивает скорость
  (14 ед/с, как в демо), нормализует вектор, держит корабль в границах системы (круг радиусом 400 ед.).
- Автопилот считает сервер: к выбранной цели, остановка в 10 ед.
- Миграция `0003_players.sql`: `players(id, token_hash UNIQUE, name, pos_x, pos_y, dir_x, dir_y, updated_at)`.
  Координаты сохраняются раз в 5 с и при отключении; при входе восстанавливаются. Новый игрок появляется у станции.
- Повторный вход с тем же токеном закрывает старую сессию (`replaced`), корабль остаётся один.
- Отключение: корабль исчезает из мира через 10 с (на случай кратковременных обрывов), позиция уже сохранена.
- Лимиты: 20 сообщений/с на сессию (как сейчас), максимум 50 игроков, размер сообщения как сейчас.

## Клиент

- `ServerGateway` (наследует `UiGateway`): подключение через существующий `WsClient`, `join` с токеном,
  преобразует `state` в формат HUD, отправляет `move`/`target`/`autopilot`. Плашка «Демо» не показывается.
- Экран подключения ведёт в космос с `ServerGateway`; кнопка «Демо» остаётся для игры без сервера.
- Переподключение: при обрыве экран показывает «Связь потеряна, переподключение…» и пробует снова (1, 2, 4, 8 с).
- Бары щита, корпуса, энергии и способности не показываются, пока сервер их не присылает (данных нет, значит не
  выдумываем). Скорость берётся из `ship.speed`.
- Интерполяция снимков и камера не меняются.

## Бот для проверки

`server/cmd/bot` (Go-утилита; запуск: `go run ./cmd/bot -url ws://127.0.0.1:8080/ws`): подключается как второй игрок, летает по
кругу. Позволяет проверить «два клиента видят друг друга» без второго телефона. Тестовый бот помечен в имени.

## Проверки (готовность этапа)

1. Go: симуляция (ограничение скорости, границы, автопилот), хранилище позиций, интеграционный тест на два
   WebSocket-клиента (видят друг друга, переподключение, `replaced`, неверный токен, `not_joined`).
2. Клиент: тесты `ServerGateway` на реальном сервере из Compose (`COSMOC_TEST_WS_URL`), существующие тесты зелёные.
3. Показ: ваш телефон + бот (+ второй клиент по желанию) в одной системе; перезапуск сервера возвращает корабль на
   сохранённое место.
4. Известные ограничения будут перечислены в отчёте (ws без TLS, токен устройства, нагрузка не измерялась).
